Обзор

Этот документ объясняет правила ESLint простым, понятным языком, чтобы команда быстро понимала, почему код помечается, и как это исправить.

Правила для TypeScript (применяются к файлам .ts/.tsx)

- Запрещены операторы non-null (`!`): не используйте `!`, чтобы заглушать проверки на null/undefined; лучше сделать явную проверку или уточнить типы.
- Запрещено использование до объявления: не обращайтесь к переменным или функциям до их объявления.
- Запрещено затенение (shadowing): не создавайте переменные с именами из внешних областей видимости.
- `require-await`: помечаются `async` функции, которые нигде не используют `await` — обычно `async` лишний.
- Порядок членов класса: поддерживайте единый порядок (поля, конструктор, публичные методы, защищённые/приватные методы).
- Явная доступность членов: указывайте `public`/`private`/`protected` там, где это требуется политикой.
- Предпочтительна optional chaining: используйте `obj?.prop` вместо длинных цепочек проверок.
- Запрет `any`: избегайте `any`, используйте точные типы или дженерики.
- Именование: константы — UPPER_CASE; переменные — camelCase или PascalCase по соглашению.

Импорты и модули

- Запрет дублирования импортов: импортируйте модуль один раз и переиспользуйте привязку.
- Ограниченные импорты: блокируются пути, соответствующие `**/internal/**` — внутренний код не должен импортироваться из вне.
- Предпочтительны именованные экспорты: избегайте default-экспортов для явности импорта.
- Сортировка импортов: `simple-import-sort` временно отключён (проблемы совместимости); для разрешения путей используется `import-x`.

FSD и границы слоёв

- Плагин `boundaries` следит за архитектурными границами: слои (`features`, `widgets`, `entities` и т.д.) могут импортировать только разрешённые слои. Для публичного доступа используйте `public-api` (баррели).

Форматирование и стиль (глобально)

- Единый стиль: точка с запятой, отступ 2 пробела, обязательный перевод строки в конце файла, двойные кавычки для строк, ограничение длины строки (130) и правила пробелов/переносов для читаемости.

Правила React (для JSX/TSX)

- Правила React применяются только к файлам с JSX. Они ловят типичные ошибки (отсутствие `key` в списках, дублирование props) и выравнивание/формат JSX (пробелы, переносы, оформление атрибутов).

JSDoc

- Требуется и проверяется JSDoc для выбранных публичных API и конструкций — это делает документацию и подсказки в редакторе надёжными.

Файлы и переопределения

- Правила, требующие типов (TypeScript), применяются только к `**/*.{ts,tsx}`, чтобы ESLint не пытался анализировать сам конфиг как TypeScript-файл.
- Проверки имён файлов (`filenames/match-regex`) временно отключены из-за несовпадения схемы плагина — можно вернуть после обновления плагина или корректировки опций.

Временно отключено

- `simple-import-sort/imports` отключён из-за несовместимости с текущим набором плагинов; можно заменить на совместимый с flat-config вариант.
- `filenames/match-regex` отключён до разрешения проблемы со схемой.

Как исключить файл конфигурации ESLint из проверки

- Добавьте `apps/frontend/eslint.config.mjs` в `apps/frontend/.eslintignore` или добавьте `ignores` в flat-config, чтобы ESLint не проверял свой конфиг.
