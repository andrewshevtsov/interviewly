# ADR: слой FSD называется `views`, а не `pages`

## Статус

Принято.

## Контекст

Feature-Sliced Design канонично называет слой со страницами `pages`. Next.js (App Router)
резолвит директорию Pages Router точно так же — по буквальному имени каталога: сначала
`pages/` в корне пакета, если её нет — `src/pages/`. Каталог с таким именем автоматически
превращается в легаси Pages Router независимо от того, используется ли параллельно App Router.

Когда в проекте появился слой `src/pages` (страницы FSD, обычные `.ts`/`.tsx` файлы без
`export default` React-компонента) и параллельно — App Router в `src/app`, `next build` начал
падать с `pages without a React Component as default export`: Next.js резолвил `src/` как
базовую директорию и для App, и для Pages Router и пытался трактовать файлы FSD-слоя `pages`
как страницы Pages Router.

## Рассмотренные варианты

### 1. App Router в корне `app/` + пустая `pages/`-заглушка (промежуточное решение)

Первым решением было вынести Next.js App Router из `src/app` в `app/` в корне пакета и
дополнительно завести пустую `pages/` в корне с README, объясняющим, зачем она нужна — Next.js
резолвит Pages Router в неё первой и не заглядывает в `src/pages`.

Работало, но не устраняло причину — маскировало конфликт заглушкой, которую легко случайно
удалить ("а что это за пустая папка?"), не разобравшись, что она блокирует автообнаружение
`src/pages`.

### 2. Переименовать слой FSD `pages` → `views` (выбрано)

Слой, который в FSD называется `pages`, называем `views` (`src/views/*`). Имя `views` не
зарезервировано Next.js ни в каком виде, поэтому конфликт устраняется полностью, а не
маскируется:

- Пустая `pages/`-заглушка в корне пакета больше не нужна — удалена.
- App Router по-прежнему живёт в `app/` в корне пакета (решение не откатывали — расположение
  `app/` вне `src/` не создаёт проблем само по себе, проблема была только в имени `pages`).
- Файлы `app/**/page.tsx` — тонкие роуты, которые импортируют компонент из `@/views/*` вместо
  `@/pages/*`; сам паттерн (App Router = роутинг, `src/views` = бизнес-логика и разметка) не
  меняется.

### 3. Полностью перейти на Pages Router (отклонено)

Раз конфликт возникает из-за Pages Router, можно было вместо этого держать стандартный роутинг
Next.js через `pages/` (в его legacy-формате: `_app.tsx`, `_document.tsx`,
`getServerSideProps`/`getStaticProps`), а слой FSD переименовать в `views`, чтобы он не совпадал
с этим `pages/`.

Отклонено: Pages Router в текущем Next.js — устаревшая модель, официально сохраняемая ради
обратной совместимости, а не рекомендуемая для новых проектов. Переход на неё означает отказ от
всего, что уже используется и проверено в проекте:

- **Server Components** — компоненты в `app/` рендерятся на сервере, их код не попадает в
  клиентский JS-бандл (проверено вручную: ни в одном загружаемом браузером чанке нет исходного
  кода наших страниц/функций). В Pages Router серверных компонентов не существует.
- **Вложенные layout'ы с сохранением состояния** — `app/layout.tsx` → `app/sessions/layout.tsx`
  не перемонтируются при навигации внутри секции. В Pages Router — один глобальный `_app.tsx`.
- **`loading.tsx`/`error.tsx` на уровне сегмента**, streaming SSR, Route Handlers
  (`route.ts`) со стандартными `Request`/`Response` — всего этого в Pages Router нет.

Выгода (более "привычное" на первый взгляд имя `pages/` в корне) не перевешивает эту потерю
возможностей.

## Решение

Вариант 2: слой FSD называется `views`. Цепочка импортов —
`app → views → widgets → features → entities → shared` (см.
[../../apps/frontend/README.md](../../apps/frontend/README.md) и
[../../apps/frontend/ESLINT-RULES.md](../../apps/frontend/ESLINT-RULES.md)).

## Последствия

- Плюс: конфликт имён устранён, а не замаскирован — не нужна пустая `pages/`-заглушка и её
  README с предупреждением "не удаляйте".
- Плюс: сохранены все возможности App Router (Server Components, вложенные layout'ы, streaming
  и т.д.).
- Минус: `views` — не каноничное имя слоя в терминологии FSD, что может на секунду сбить с толку
  того, кто уже работал с FSD в других проектах (митигируется этим ADR и комментариями в коде).
