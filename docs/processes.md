# Процессы и регламенты

## 1. Расписание активностей

- **Понедельник, 12:00** - еженедельный planning: ставим цели на итерацию.
- **Пятница, 12:00** - еженедельный review/retro: демо сделанного + отчёт на Тимура. Между
  собой обсуждаем, что улучшить (в т.ч. в процессах).
- **По необходимости** - ежедневный созвон на 15 минут (текстовый статус в чате, если нет
  проблем/блокеров).
- **Отчёт Тимуру** - ссылки на Storybook сделанных UI-компонентов, статус интеграции
  бэк-фронт, блокеры, если есть.

## 2. Правила ведения задач

- Workflow статусов: `Backlog → To Do → In Progress → Code Review → Testing → Done`.
- Definition of Done (DoD) - задача считается сделанной, когда:
  - код влит в `dev`;
  - пройдено ревью;
  - автотесты зелёные;
  - фича задеплоена в **[уточнить окружение]**;
  - документация обновлена.
- Одна задача = один ответственный.
- Запрещено держать больше двух задач в `In Progress` одновременно.

## 3. Ветки и коммиты

- Пуш в `dev`/`master` напрямую запрещён - только через PR с код-ревью.
- Релизы - через отведение ветки и нажатие кнопки Release в GitHub.
- `main` всегда стабилен и готов к выкатке.

Формат коммитов и именование веток - см. [style-guide.md](style-guide.md).

## 4. Ревью и качество кода

- Любой код в основную ветку - через Pull Request.
- Минимум 2 аппрува от другого разработчика.
- До человеческого ревью обязаны пройти: линтеры (в т.ч. проверка соблюдения границ FSD),
  форматтеры, базовые автотесты.
- Минимум кастомных стилей по месту - используем разработанный UI kit.
- Обязателен CI-пайплайн.
- На каждый PR прогоняются: линтеры, тесты, билд проекта, typecheck через TypeScript.

## 5. Инструментарий

- Общий чат - Telegram.
- Таск-трекер - GitHub Projects (доступ через тимлида).
- Git-репозиторий - [github.com/andrewshevtsov/interviewly](https://github.com/andrewshevtsov/interviewly).

возможности ведёт от API до UI. Взаимопомощь приветствуется.
