# Витрина участников

Участники ищут партнёра для пробного интервью. Карточка на витрине - это профиль пользователя
(`Profile`, 1:1 с `User`), у которого включён флаг `showcaseVisible`.

## Правила

- Профиль скрыт, пока пользователь сам не включит `showcaseVisible` (`PUT /profiles/me`).
  Включить можно только с непустыми ролью и стеком, иначе 400.
- Если `showcaseVisible` не передан в `PUT /profiles/me`, значение не меняется.
- На витрине только пользователи со статусом `ACTIVE`; свою карточку смотрящий не видит.
- Отдаются имя (имя + фамилия из `User`), роль, уровень, стек, bio, число интервью и признак
  «сейчас в сессии». Email, telegram и оценки из отзывов не отдаются: отзывы приватны.
- `interviewsCount` считается как в [лидерборде](leaderboard.md): завершённые сессии, в которых
  участник был.
- `inSession` - участник сейчас в сессии со статусом `ACTIVE` (`leftAt` не задан).

## API

```text
GET /showcase/cards        JWT
  ?level=junior&level=middle   любой из уровней (регистр не важен: SENIOR = senior)
  &stack=React&stack=Go        любая из технологий; тег целиком, регистр не важен: React = react = REACT
  &q=ivan                      имя, фамилия, роль (подстрока) и тег стека (целиком); регистр не важен
  &limit=20                    1..50, по умолчанию 20
  &cursor=<nextCursor>         курсор из предыдущего ответа (uuid)
→ { items: [{ id, name, role, level, stack, bio, interviewsCount, inSession }], nextCursor }
```

Поиск не зависит от регистра: стек хранится так, как его ввёл пользователь (`React`), а искать по нему можно как угодно. Для этого есть копия в нижнем регистре `Profile.stackSearch`, которую ведёт триггер БД, писать её руками не нужно. Тег совпадает целиком: `stack=rea` не найдёт React; подстрока ищется только в `q` и только по имени, фамилии и роли.

Порядок: новые карточки выше (`createdAt desc, id desc`), поэтому курсор стабилен. `nextCursor`
равен `null` на последней странице. `id` - идентификатор карточки (профиля), по нему подаётся отклик.

## Отклики

Откликнуться можно на карточку, которая есть на витрине (профиль включён, владелец `ACTIVE`),
независимо от того, чем владелец занят прямо сейчас. Откликающийся сразу указывает **роль**
(`INTERVIEWER` или `CANDIDATE`; владелец карточки получает противоположную) и **время встречи**.

**Время встречи**
- ISO-8601 с часовым поясом (`Z` или `+04:00`); без пояса 400.
- От 3 часов до 30 дней от текущего момента.
- Длительность для проверки пересечений - 60 минут: слоты, чьё начало ближе часа, пересекаются.

**Правила**
- Откликаться может только пользователь с заполненным профилем; на свою карточку нельзя (403).
- Откликов на одну карточку может быть сколько угодно (владелец выбирает между ними), но у одного
  человека - один отклик в ожидании на карточку.
- Нельзя откликнуться на время, которое пересекается с: назначенными интервью откликающегося, его
  собственными откликами в ожидании, назначенными интервью владельца карточки. Ответ 409 просит
  предложить другое время. Чужие отклики на карточку владельца не мешают: он как раз выбирает.
- Откликнувшийся может отозвать отклик, пока он в ожидании (`CANCELLED`); пауз после отзыва нет.
- Владелец принимает или отклоняет. Отказ требует причину 100-500 символов (после trim); те же границы
  проверяет CHECK в БД. Причину видит откликнувшийся.
- После отказа повторный отклик на ту же карточку - через 48 часов, **если владелец не отметил
  `timeMismatch`** (отказ только из-за времени): тогда можно сразу предложить другое время.
- Решённый отклик повторно решить нельзя (409), в том числе при двух одновременных запросах.
- Отклик в ожидании, у которого прошло время встречи, получает статус `EXPIRED` (при обращении к
  спискам и откликам; фоновая задача появится вместе с очередью) и не мешает новому отклику.

**Принятие создаёт сессию.** В одной транзакции: проверка, что оба свободны в это время (иначе 409 и
совет отклонить с `timeMismatch`), статус `ACCEPTED`, сессия `MOCK` / доступ `INVITE` / статус
`SCHEDULED` на `scheduledAt`, оба участника сразу в `SessionParticipant`. Владельцем сессии становится
**интервьюер пары**, а не автор карточки: по модели комнат владелец всегда `INTERVIEWER`. Если
откликнувшийся выбрал `INTERVIEWER`, владельцем будет он. Принять можно, пока время не наступило.
Ответ содержит `sessionId` и `reminderAt` (за 2 часа до встречи бот пришлёт обоим ссылку на
комнату) - по ним интерфейс показывает сообщение. Блокировка участников (`pg_advisory_xact_lock`)
не даёт двум параллельным запросам пропустить пересекающиеся слоты.

Отменить назначенную встречу могут оба участника, владелец и admin: `POST /sessions/:id/cancel`
(см. [rooms.md](rooms.md)).

```text
POST /showcase/cards/:cardId/responses     { role, scheduledAt }
GET  /showcase/responses/incoming[?status=PENDING|ACCEPTED|REJECTED|CANCELLED|EXPIRED]
     → { id, status, role, ownerRole, scheduledAt, responder: { name, title, level, stack, bio },
         sessionId, rejectionReason, timeMismatch, ... }
GET  /showcase/responses/outgoing
     → { id, status, role, scheduledAt, card, sessionId, rejectionReason, timeMismatch, canRetryAt, ... }
POST /showcase/responses/:id/accept                               только владелец карточки
POST /showcase/responses/:id/reject        { reason, timeMismatch? }   только владелец
POST /showcase/responses/:id/cancel                               только автор отклика
```

Контакты откликнувшегося (email, telegram) в списках не отдаются. Списки отдают последние 50 откликов.
О каждом новом отклике владельцу карточки, о принятии и отказе откликнувшемуся (и о отмене встречи
второму участнику) приходит уведомление в Telegram или на почту, а за 2 часа до встречи обоим приходит
ссылка на комнату: см. [notifications.md](notifications.md).

## Сид

Все сид-профили включены на витрине, кроме `owner@interviewly.test` - чтобы проверять скрытие.
