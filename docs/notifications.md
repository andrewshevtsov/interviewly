# Уведомления

Backend отправляет уведомления о матчах из [витрины](showcase.md) и напоминание о встрече.
Каждый получатель получает сообщение в **Telegram, если он привязан, иначе на почту**.

## Что отправляется

| Событие | Кому | Содержание |
|---------|------|------------|
| Новый отклик (каждый, включая повторный) | владельцу карточки | кто откликнулся, предложенное время в его часовом поясе, роли обоих |
| Отклик принят | откликнувшемуся | кто принял, время встречи в его часовом поясе, его роль, обещание ссылки за 2 часа |
| Отклик отклонён | откликнувшемуся | причина, время повтора (или «можно сразу предложить другое время» при `timeMismatch`) |
| Встреча отменена (`POST /sessions/:id/cancel`) | второму участнику (отменившему не шлём) | кто отменил, время, причина |
| За 2 часа до встречи | обоим участникам | ссылка `FRONTEND_URL/sessions/:id`, партнёр, роль |

Если до встречи меньше 2 часов, ссылка уходит сразу при принятии. Напоминание снимается при отмене
встречи, а перед отправкой обработчик проверяет, что встреча не отменена и не началась.
Время показывается в `User.timeZone` получателя, без него - в UTC с пометкой. Если пояс не задан, фронт один
раз сохраняет пояс браузера (`features/sync-time-zone`, `PATCH /users/me`); сохранённый не перезаписывается.

## Выбор канала

1. Есть `User.telegramId` - сообщение в Telegram.
2. Telegram отверг навсегда (бот заблокирован, чата нет, неверный токен: ответы 4xx кроме 429) - письмо.
3. Временный сбой Telegram (сеть, 5xx, 429) - повтор заданием, на почту не переключаемся.
4. Нет `telegramId` - письмо на `User.email`.
5. Пользователь вошёл через Telegram и реального email у него нет (`tg-<id>@telegram.interviewly.local`) -
   писать некуда, сообщение пропускается с записью в лог.

Писать пользователю бот может, только если он вошёл или привязал Telegram через Telegram Login Widget
(виджет просит право писать, `data-request-access="write"`) или сам нажал `/start` у бота.

## Привязка Telegram

- В личном кабинете (блок «Telegram-уведомления») виджет вызывает `POST /auth/telegram/link`; 409 - этот
  Telegram уже привязан к другому аккаунту.
- Отвязка: `DELETE /users/me/telegram`, дальше уведомления идут на почту. 409, если у аккаунта только
  служебный адрес `tg-<id>@telegram.interviewly.local` (иначе пропал бы единственный вход).

## Webhook бота

`POST /telegram/webhook` принимает апдейты бота. Сейчас бот отвечает только на `/start` в личном чате
подсказкой привязать Telegram на сайте. Запрос принимается, только если заголовок
`X-Telegram-Bot-Api-Secret-Token` совпадает с `TELEGRAM_WEBHOOK_SECRET`; без секрета в окружении endpoint
отвечает 401 всегда. Если задан `TELEGRAM_WEBHOOK_URL`, backend регистрирует webhook при старте
(`setWebhook`, ошибка только логируется). Один webhook на бота: при локальной проверке он принадлежит
тому backend'у, который стартовал последним.

## Как устроено

```text
домен (respond / accept / reject / cancel)  ──▶  NotificationsService  ──▶  очередь «notifications» (BullMQ, Redis)
                                                                    │
            событие: response-created / response-accepted / response-rejected /        ▼
                     session-cancelled / session-reminder      NotificationsProcessor
                                                                    │ собирает сообщения для людей
                                                                    ▼
                                                      задание deliver на каждого получателя
                                                      (5 попыток, экспоненциальная пауза от 5 с)
                                                                    │
                                              NotificationDeliveryService ──▶ Telegram или почта
```

- Уведомления вторичны: сбой очереди (Redis недоступен, таймаут 3 с) пишется в лог и **не ломает**
  основную операцию (принять отклик, отменить встречу).
- Доставка каждому получателю - отдельное задание со своими повторами: сбой одного не приводит к
  повторному письму другому. Детерминированные `jobId` не дают повтору события создать дубль.
- Напоминание - отложенное задание `session-reminder-<sessionId>`. Redis запущен с AOF
  (`--appendonly yes`), чтобы отложенные задания переживали его перезапуск.
- Код: `src/modules/notifications/`, каналы - `src/infrastructure/telegram/`, `src/infrastructure/email/`.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `TELEGRAM_BOT_TOKEN` | - (обязательна) | токен бота из @BotFather |
| `TELEGRAM_API_URL` | `https://api.telegram.org` | менять только в тестах (заглушка API) |
| `TELEGRAM_WEBHOOK_SECRET` | - | секрет webhook; без него `/telegram/webhook` отвечает 401 |
| `TELEGRAM_WEBHOOK_URL` | - | публичный URL webhook; если задан, регистрируется при старте |
| `REDIS_URL` | `redis://localhost:6379` | очередь; в Docker `redis://redis:6379` задаёт compose |
| `SMTP_HOST`, `SMTP_PORT` | `localhost`, `1025` | в разработке - Mailpit |
| `SMTP_USER`, `SMTP_PASSWORD` | - | если SMTP требует авторизацию |
| `MAIL_FROM` | `Interviewly <no-reply@interviewly.local>` | отправитель |
| `FRONTEND_URL` | `http://localhost:3000` | база ссылки на комнату |

## Локальная проверка

```bash
pnpm db-dev        # postgres, livekit, redis, mailpit
pnpm back-dev
```

- Письма видны в Mailpit: http://localhost:8025.
- Напоминание можно не ждать: принять отклик на время «через 3-4 часа» и принудительно запустить задание
  (`job.promote()` у `session-reminder-<sessionId>` в очереди `notifications`).
- **Осторожно: все локальные backend'ы на одном Redis делят одну очередь.** Задание может забрать
  воркер другого запущенного backend'а (например, `back-dev` в соседнем окне) с его настройками
  Telegram и SMTP. Для изолированной проверки запускайте второй backend с другой базой Redis:
  `REDIS_URL=redis://localhost:6379/1`.

### Проверка с настоящим ботом

Через ngrok (туннели на фронт и бэк - как в
[telegram-auth-tunnel-testing.md](dev/telegram-auth-tunnel-testing.md), дополнительно задайте
`TELEGRAM_WEBHOOK_SECRET` и `TELEGRAM_WEBHOOK_URL=https://<домен-туннеля-бэкенда>/telegram/webhook`):

1. Войдите по email, откройте личный кабинет через домен фронт-туннеля и привяжите Telegram виджетом.
2. Напишите боту `/start` - придёт подсказка (проверка webhook).
3. Запустите сценарий (принять / отклонить отклик, отменить встречу): сообщение придёт в Telegram.
